# I2C 窓際テスト

[English](../i2c-window-test.md) | 日本語

[セットアップ](setup.md) · [Python・C API](api.md)

`examples/i2c_window_test.py` は、既存の `CXD56xx` API で指定時間だけ観測し、
通信と測位を別々に集計します。ドライバーの起動シーケンスは変更しません。

## 実行前の確認

- 実機のボード型番を確認する。
- SDA・SCL・IRQIN の 1.8 V ↔ 3.3 V レベル変換、共通 GND、電源、アンテナを確認する。
- `gpiodetect` と `gpioinfo` で IRQ の接続先を確認し、そのチップを指定してドライバーをビルドする。
- I2C が 400 kHz、ドライバーのアドレスが `0x24` であることを確認する。
- 同じモジュールを使用している別プロセスを終了し、アンテナを空の見える窓際に置く。

## 実行

ドライバーをインストールした仮想環境を有効にし、リポジトリのルートで実行します。

```sh
python examples/i2c_window_test.py \
  --duration 600 \
  --board-model '現物で確認した型番'
```

デフォルトでは 0.2 秒ごとにスナップショットを読み、30 秒ごとに座標を含まない進捗を表示します。
`--interval` で読み取り間隔、`--duration` で観測秒数を指定できます。
15 分間の観測は `--duration 900` です。Ctrl+C でも途中結果を保存して終了します。

無人実行でネイティブドライバーの停止待ちも制限する場合は、外側にタイムアウトを設定します。
強制終了になった場合は `summary.json` が完成しない可能性があるため、実行結果と生ログを確認してください。

```sh
timeout --signal=INT --kill-after=15s 660s \
  python -u examples/i2c_window_test.py --duration 600 --board-model '現物で確認した型番'
```

## 保存されるログ

保存先は `$XDG_STATE_HOME/rpi-cxd56xx-gnss/<UTC時刻>/`、未設定時は
`~/.local/state/rpi-cxd56xx-gnss/<UTC時刻>/` です。
`--log-dir` で未作成のディレクトリを指定することもできます。
Git 作業ツリー内への保存は拒否します。新規ログディレクトリは所有者のみアクセスできます。

| ファイル | 内容 |
| --- | --- |
| `samples.jsonl` | ホスト時刻、経過時間、API 戻り値、受信時刻、座標、Fix、衛星数、DOP |
| `driver.stderr.log` | C ドライバーを含む標準エラー出力。起動・終了時のエラーも含む |
| `summary.json` | 通信・Fix 判定、初回通知・初回Fixまでの秒数、更新間隔、最大衛星数、最終スナップショット |

`samples.jsonl` と `summary.json` には位置情報が含まれます。Git に追加しないでください。

## 判定の意味

- 通信成功：`peek()` が一度以上 `0` を返した。初期化できただけでは成功としない。
- 継続更新：異なる受信 `timestamp` を二つ以上観測した。同じキャッシュを読んでも更新回数は増えない。
- 測位成功：`mode` が 2 または 3、`status` が 1（通常のFix）または 2（Differential GPSの有効なFix）、
  座標が数値の有効範囲内で、受信時刻の更新を最近観測した。`mode=2` は2D、`mode=3` は3D。
- 初回Fix時間：このテストのドライバー初期化開始からの時間。コールドスタートの TTFF ではない。
- 更新間隔：受信時刻の正の差と、ホストが更新を検出した時刻の差を別々に集計する。
  ホスト側の測定には読み取り間隔の分解能があり、受信時刻の逆行は別に数える。
- `used_sats`：既存APIの追尾フラグ数。同じ衛星の別信号を別項目として数えるため、
  測位計算に使われた衛星数や、重複を除いた衛星数ではない。
- 座標の範囲判定：緯度 ±90 度、経度 ±180 度。実際の設置場所との一致や精度は別途確認する。

`close_success` は停止応答の確認とリソース解放の成功を表します。停止時のエラーも
`errors` に記録され、終了コードは `1` になります。

`completed` は指定時間の観測が終了したかを表します。通信・測位の合否とは独立です。
初回Fix後に更新が止まった場合でも `fix_success` は過去の成功を保持するため、
`last_timestamp_update_age_s`、最終スナップショット、生ログも合わせて確認してください。
初期化失敗が `peek()` に伝わらず待機が続く場合もあるため、`driver.stderr.log` も確認が必要です。

終了コードは、通常終了が `0`、例外・読み取りエラーが `1`、通知未受信が `2`、
観測中の中断が `130` です。Fix 未成立だけを理由にエラー終了にはしません。
